# 专题讲解内容编写规范

> 本文档是重写 `src/data/topics/*.ts` 中知识点讲解的唯一标准。所有内容必须遵守本规范，
> 以保证渲染正确、质量统一。

## 1. 数据格式（极易出错，必读）

每个专题的 `content` 字段是 **`String.raw` 模板字符串**：

```ts
content: String.raw`## 一、直觉引入

……正文……`
```

规则：

1. **LaTeX 反斜杠一律写单反斜杠**：`\lim`、`\frac{a}{b}`、`\sum_{k=0}^{n}`。
   绝对不要写双反斜杠（`\\lim` 会渲染出字面量 `\\lim`）。
2. **禁止出现 `${`**：String.raw 中 `${` 会被当作 JS 插值导致报错。
   数学里不会用到它；若不慎写了，改成 `\$ {` 中间加空格或改写公式。
3. **禁止在正文中使用反引号 `` ` ``**（会提前终止模板字符串）。
4. 除 `content` 外，其他字段（`id`、`courseId`、`chapter`、`title`、`summary`、
   `keyPoints`、`relatedProblemIds`）**必须与原文件逐字一致，一个字符都不能改**。
   校验脚本会逐一比对，改错即失败。

## 2. 支持的 Markdown + LaTeX 语法（渲染器子集）

| 语法 | 写法 | 说明 |
|------|------|------|
| 二级标题 | `## 标题` | 章节主标题 |
| 三级标题 | `### 标题` | 例题标题 |
| 四级标题 | `#### 标题` | 慎用 |
| 加粗 | `**文字**` | 仅行内 |
| 行内公式 | `$x^2 + y^2 = r^2$` | 嵌在段落里 |
| 独立公式 | `$$...$$` | **必须单独占行**，前后留空行 |
| 无序列表 | `- 条目` | 行首 |
| 有序列表 | `1. 条目` | 行首 |
| 引用块 | `> 内容` | 行首，用于"直观理解""注意"等 |
| 表格 | `\| a \| b \|` + `\|---\|----\|` | 第二行是分隔行 |

渲染器**不支持**：行内代码、链接、图片、分割线、`*斜体*`、HTML。
公式环境只支持 KaTeX 支持的：`cases`、`pmatrix`、`bmatrix`、`vmatrix`、`aligned` 等。

## 3. 内容结构（每个专题固定七节）

每个专题的 `content` **必须**按以下结构组织（标题文字可微调，但七节都要有）：

```markdown
## 一、直觉引入：从一个问题说起

用生活场景、几何图像或历史动机引出这个知识点。让读者感到"这东西是干嘛的、
解决什么痛点"。2~4 个自然段，可以提一个引子问题（先不解答，后文呼应）。

## 二、严格定义

给出精确定义。每个符号首次出现时说明含义；条件逐条列出并解释；
有多个等价定义时给出最重要的一个，其余以列表补充。

## 三、为什么这样定义

逐条解释定义中每个条件的动机：去掉它会出什么反例？
这一节是"易懂"的关键——把定义的每个零件拆开讲。
至少给出一个"条件不可去"的反例。

## 四、直观理解与图像

几何图像、类比（用熟悉的事物比喻）、正误对比表。
多用表格与引用块。让读者建立"手感"。

## 五、例题精讲

### 例 1（基础：直接套定义）

题目：……

分析：……

解：……（完整演算，每一步写清楚依据）

### 例 2（进阶：综合运用）

题目：……

分析：……

解：……（完整演算）

### 例 3（拔高：易错或含陷阱）

题目：……

解：……（完整演算 + 点评"这题坑在哪"）

每个例题必须有完整演算过程，不能只写答案。公式用 $$...$$ 独立展示关键步骤。

## 六、常见错误与陷阱

用列表逐条给出：错误做法 → 为什么错 → 正确做法。至少 4 条。

## 七、小结与口诀

要点回顾（列表）+ 一句帮助记忆的口诀（加粗）。
```

## 4. 质量要求

1. **篇幅**：每个专题 `content` 3000~4500 个汉字（不含公式与 Markdown 符号也应有
   2000+ 汉字正文）。现有内容平均只有 1100 字，必须成倍扩充。
2. **正确性第一**：所有定义、定理、演算必须数学上严格正确。拿不准的结论不要写。
3. **易懂**：假设读者是刚学这门课的大二学生。专业术语第一次出现时用白话解释。
   多用"换句话说""也就是说""你可以把它想成"。
4. **例题演算完整**：不允许"易证""略""显然"。每一步给理由。
5. **前后呼应**：引子问题在第五节或第七节给出回应。
6. 公式变量与现有内容保持一致（如该课程惯用 $x_0$ 就不用 $a$）。
7. 中文排版：汉字与公式之间自然留白；标点用中文全角；数字序号统一。

## 5. 自检命令（写完必须运行）

```bash
cd /workspace/frontend && npx tsx scripts/check-topic.ts src/data/topics/<文件名>.ts
```

要求：**0 个错误**。警告（字数、小节数）也应消除。
常见失败原因：公式少了右括号 `}`、`$` 不成对、元信息字段被改动。
